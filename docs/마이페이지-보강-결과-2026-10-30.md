# 마이페이지 보강과 안 쓰던 API 붙이기 결과 (2026-10-30)

## 요청

- 사용자: "마이페이지가 너무 부실하다" → 보완 기능 예시 다섯(한눈에 보기, 투자유형 채우기, 가입 경로, 검사 없이 성향 바꾸기, 최근 본 백테스트)을 드렸고
  "5개 다 개발해봐. 백엔드 API를 보고 아직 안 넣은 기능도 다 넣어봐. 단추도 붙일 수 있는 거 다 붙이고. UI 스킬을 써서 여러 페이지와 비슷하게."
- 디자인은 2026-10-30 재정비 규칙 그대로다(흰 바탕, 2px 먹 선으로 구역 시작, 1px 선으로 행 구분, 밑줄 탭, 단추 세 종류, 빨강·파랑은 등락만).
  새로 만든 눈에 띄는 것은 하나 — 다섯 성향 눈금(`PersonalityScale`)이다. 안정형에서 공격투자형까지 실제로 차례가 있는 값이라 한 줄 자로 그렸다.

## 제안 다섯 개를 어떻게 했나

| 제안 | 결과 |
|---|---|
| 1. 첫 화면을 요약으로 | `/mypage` = 한눈에 보기. 내 정보 한 줄, 내 투자성향, 관심종목(오늘 크게 움직인 4종목), 최근 본 백테스트, 최근 AI 대화. 칸마다 따로 받고 따로 실패한다 |
| 2. 투자유형 탭 채우기 | 다섯 성향 눈금 + 둘러보기 칸. "내 전략으로 백테스트"는 그 전략을 골라 둔 채 백테스트로 간다 |
| 3. 가입 경로 표시 | 한눈에 보기 첫 줄과 내 정보 표에 "구글로 가입한 계정"(로그인 단추와 같은 아이콘) |
| 4. 검사 없이 성향 바꾸기 | **저장 단추는 만들지 않았다.** `PATCH /api/members/me/personality`는 성향 이름이 아니라 DB 자동 번호를 받고, 그 번호는 코드가 아니라 DB에 직접 넣은 값이라 화면이 알 수 없다(남은 일 백엔드 8, 2026-09-23 검사 M-7 "추측해 보내지 않는다"). 추측해 보내면 다른 성향이 조용히 저장될 수 있다. 대신 다섯 성향을 둘러보고 그 전략으로 백테스트할 수 있게 했고, 다른 성향을 보면 "바꾸려면 검사를 다시 해 주세요"를 둔다. 서버가 이름이나 1~5로 받으면 이 칸에 저장 단추만 붙이면 된다 |
| 5. 최근 본 백테스트 | 결과를 받을 때마다 이 브라우저에 남긴다(10줄, 같은 조합은 한 줄). 화면이 "이 브라우저에서 본 결과만 남아요"라고 밝힌다. 줄을 누르면 같은 종목·전략·기간으로 한 번 계산한다. 로그아웃·탈퇴 때 지운다 |

## 백엔드 API를 보고 더 붙인 것

스웨거(`GET /v3/api-docs`, 2026-10-30 받음)의 경로 30개(요청 38가지)를 화면 코드와 대조했다. 화면이 안 쓰던 사용자용 API는 셋이었다.

| API | 붙인 곳 | 요청 규칙 |
|---|---|---|
| `GET /api/news?query=`(네이버 뉴스 검색, 로그인) | 주식 모아보기 맨 아래 "관심종목 뉴스" — 종목 이름 밑줄 탭 | 고른 종목 하나만. 처음엔 담은 순서의 첫 종목. 같은 검색어 10분 메모 |
| `GET /api/vectordb/search?question=&stockName=`(질문과 가까운 뉴스 3건, 로그인) | 종목 상세 뉴스 탭의 세 번째 "물어서 찾기" | 누를 때만. 상세를 열 때 요청은 그대로 |
| `PATCH /api/members/me/personality` | 붙이지 않음(위 4번) | — |

붙이지 않은 것: 증권사 직통 `/api/market/**` 넷(일자별 시세 둘, 거래량 순위, 휴장일)은 "증권사 호출은 상세 화면과 홈 카드 그래프뿐" 규칙에 걸린다.
관리용 `POST /api/initiate`·`POST /api/vectordb/all`·`GET /api/vectordb`·`/api/token/*`는 사용자 기능이 아니다. `/api/market/{code}/price`는 이미 토큰 심기에 쓴다.
대화방 목록(`GET /api/chat-sessions`)은 AI 화면이 쓰던 것을 마이페이지에서도 쓴다(응답의 `updatedAt`을 처음 읽는다).

## 판정 기대값 (판정 전에 적음)

- 공통(대비 4.5:1, 포커스 보임, 375에서 44px, 320~1920 가로 넘침 0, 등락 색은 등락에만, 색 직접 입력 0, 실제 백엔드 0): 새 화면 셋
  (`mypage`, `personality-browse`, `stock-ask`)을 더한 19화면 모두 통과.
- 요청: 기존 화면은 고치기 전과 같다. 예정된 차이는 주식 모아보기(옛 주소 `/mypage/likes` 포함)에 뉴스 1건(`GET /api/news?query=삼성전자`).
  한눈에 보기는 GET 넷, 물어서 찾기는 누른 뒤에만 1건.
- 흐름: 최근 본 줄 → 그 조합 프리셋 요청 1번과 결과, 새로고침해도 다시 계산하지 않음. 내 전략으로 백테스트 → 전략칸만 채우고 요청 0.
  최근 AI 대화 줄 → 그 방 상세 1건, 새 방 0. 로그아웃 → 기록 `[]`. 관심종목 담기 200/409/500 → 각각의 안내.
  관심종목 뉴스: 처음 1건, 탭을 바꾸면 그 종목 1건, 되돌아오면 0건. 물어서 찾기: 탭만 누르면 0건, 찾기 1건, 비로그인은 안내만.

## 주의할 점

- 최근 본 백테스트는 이 브라우저에만 있다. 다른 기기에서는 보이지 않는다(화면이 그렇게 적는다).
- 네이버 뉴스 검색은 회원 모두가 네이버 하루 한도를 나눠 쓴다. 쓰는 사람이 늘면 서버 캐시가 필요하다(남은 일 8).
- 이 브랜치를 main에 합치면 디자인 재정비 때와 같이 홈의 예시 커뮤니티 글과 예시 지수 값도 함께 운영에 뜬다(남은 일 6·7).
- 판정용 가짜 응답에서 `/api/vectordb/search`의 날짜(`pubDate`)는 백엔드 소스대로 네이버 형식으로 지었다. 실서버 응답 모양은 확인하지 않았다(규칙).
