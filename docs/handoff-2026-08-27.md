## 2. 새로 생긴 구조 (코드만 봐서는 안 보이는 것)

`CLAUDE.md`에 각각의 절이 있다. 여기서는 **왜 그렇게 갈라 뒀는지**만 적는다.

### 미리받기가 두 겹이다

| | 언제 | 누가 |
| --- | --- | --- |
| `src/pages/lazy.ts` | **앱 안에서** 옮겨 다닐 때 | 홈의 idle 미리받기, 헤더 hover |
| `plugins/route-preload.ts` | **주소를 직접 치고** 들어왔을 때 | 빌드가 `<head>`에 심는 script |
| `src/api/warmup.ts` | 위 둘은 **파일**, 이건 **데이터** | `main.tsx`, 링크 pointerdown |

후자 둘은 앱이 아직 없거나(주소 직접 입력) 화면이 그려지기 전이라 평범한 방법으로는
못 한다. 셋 다 **"주소만 보면 어느 화면인지 안다"**는 같은 사실에 기댄다.

### `api/warmup.ts`는 캐시가 아니다

한 번 가져가면 지운다(`takeWarmStockDetail`). 시세는 초 단위로 바뀌는 값이라 들고
있다가 나중에 내주면 **옛날 값을 새 값인 척** 보여주게 된다.

**`<head>`에서 fetch를 먼저 던지는 방법이 두 배 넘게 빠르지만(최대 1.2초) 안 골랐다.**
fetch 창구가 `client.ts` 말고 하나 더 생기고, 브라우저가 그것을 앱의 요청과 같은 것으로
쳐 주지 않으면 조용히 두 번 부른다. 이 창구는 백엔드에서 **KIS를 1건 부른다.**

⚠️ **마우스를 올릴 때(hover) 데이터를 부르면 안 된다.** 표를 훑기만 해도 수십 건이
나가고, 그게 홈이 102종목을 몰아쳐 계정 경고를 받은 그 자리다. 누르기(`pointerdown`)는
실제로 옮겨 가는 1회당 1건이라 낭비가 없다 — 눌렀다 취소하면 1건이 버려지는데
그건 알고 감수한 것이다.

### 라우트가 세 곳에 적혀 있다

`App.tsx` / `lazy.ts` / `vite.config.ts`의 `routePreload`. 자세한 표는 `CLAUDE.md`에 있다.
핵심은 **어긋나는 방향이 안전한 쪽**이라는 것 — 파일 이름이 틀리면 빌드가 실패하고
(일부러 틀리게 넣어 확인함), 주소가 틀리면 그 화면만 조용히 느려질 뿐이다.

## 3. ⚠️ 재는 방법에서 밟은 함정 (이게 이 문서에서 제일 오래 쓸모 있다)

숫자는 코드를 보면 다시 알 수 있지만, **틀리게 재는 방법은 같은 도구를 쓰면 또 밟는다.**
전부 실제로 겪은 것이고, 전부 **나에게 유리한 쪽으로** 틀렸다.

| 함정 | 무슨 일이 났나 | 어떻게 했나 |
| --- | --- | --- |
| **`route.fulfill`이 속도 제한을 건너뛴다** | 글꼴 A/B에서 가변 쪽만 HTML을 Playwright가 내줘서 그 회차만 출발이 빨랐다. `-217ms`로 쟀는데 실제는 `-72ms` | 양쪽 다 진짜 빌드를 받게 하고, 바꾸는 쪽은 `git stash`로 갈아 끼운다 |
| **스크린샷 자체가 느리게 만든다** | 40ms마다 `page.screenshot()`을 찍어 흰 화면을 재니 3,024ms. CDP `Page.startScreencast`로는 647ms | 화면 시간은 페이지 **안에서** `performance.now()`로 잰다 |
| **내가 넣은 `waitForTimeout`이 결과에 섞인다** | '결과 보기'를 1,849ms로 보고. 실제 348ms | 대기와 측정을 섞지 않는다 |
| **`click()`은 누르고 떼는 사이가 0ms다** | pointerdown 미리받기 이득이 통째로 사라져 `-30ms`로 나왔다. 사람 손(90ms)으로 누르니 `-130ms` | `mouse.down()` → 대기 → `mouse.up()` |
| **찾는 요소가 출발 화면에도 있다** | `waitForSelector('h1')`이 홈의 h1에 즉시 걸려 이동 시간이 0에 가깝게 나왔다 | 목적지에만 있는 글자로 찾는다 |
| **눈금이 껍데기에도 있다** | `/전일 대비/`는 데이터 없이도 그려져서 "시세 표시"가 112ms로 나왔다. 실제 339ms | 데이터가 와야 생기는 것으로 잡는다(`장 기준`) |
| **Vite의 `?t=` 쿼리** | stub이 쿼리 없이 `error.ts`를 부르면 **모듈이 두 벌** 로드돼 `instanceof`가 전부 깨진다 | 진짜 모듈이 쓰는 URL을 실행 중에 읽어 그대로 쓴다 |
| **`**/api/**` 라우트가 소스도 잡는다** | 개발 서버의 `/src/api/*.ts`까지 가로채 MIME 오류가 났다 | `http://localhost:5199/api/**` 처럼 절대 URL로 |
| **404인데 가벼워 보인다** | 글꼴 경로에서 `static/`을 잘못 지웠더니 "1건 0KB". 안 붙은 것을 빨라진 것으로 읽을 뻔했다 | 요청 **수**와 `document.fonts.size`로 확인 |
| **낡은 서버가 옛 코드를 준다** | 5일 전 vite가 포트를 잡고 있었다 | 재기 전에 포트 주인을 확인 |

**재는 자리 두 개는 늘 나눠서 본다.** ① 파일이 도착한 시각(`responseEnd`)과 ② 화면에
글자가 박힌 시각은 다르다. 어제 한 일들이 대부분 ①만 크게 당기고 ②는 조금 당겼다 —
그리는 데는 어차피 `index.js`가 다 와야 하기 때문이다.

### 쓰던 도구

- `playwright-core` + `channel: 'chrome'` (스크래치패드의 `node_modules`에 있다)
- 느린 회선: CDP `Network.emulateNetworkConditions` — 1.5Mbps / 지연 150ms
- 느린 기기: CDP `Emulation.setCPUThrottlingRate` — `rate: 4`
- 레이아웃 밀림: `PerformanceObserver` `layout-shift`, `buffered: true`
- 배포본 확인: `npm run build && npx vite preview --port 4188`
  (**`vite preview`는 `server.proxy`를 물려받는다** — API가 진짜로 나간다)

## 5. 백엔드에 물어봐야 진도가 나가는 것

8/21 문서 §5의 네 가지가 **그대로 남아 있다.** 그 뒤로 둘이 늘었다.

1. **성향 번호표** — `SELECT id, invest_personality FROM personality;`
   `utils/personality.ts`의 `PERSONALITY_IDS`가 **추정값**이다.
   ⚠️ 지금 방어는 **탐지지 예방이 아니다.** 바꾼 뒤 다시 조회해서 다르면 경고를 띄우는데,
   그 시점에는 **서버에 이미 틀린 값이 저장된 뒤다.** "틀렸다는 걸 알 수는 있다"가 맞는 말이다.
2. **종목 상세 실시간** — `StockDetailRes`에 오늘 봉이 없다.
3. **로그인 돌아오는 길** — `OAuth2SuccessHandler`가 `sendRedirect` 대신 JSON을 그린다.
   프론트는 이미 다 돼 있다.
4. **홈 시세** — `GET /v1/home`
5. **뉴스 502** — `/api/stocks/{code}/news`가 2026-08-25부터 계속 502다.
6. **🆕 `/api/stocks/**` 응답 압축** — 45KB JSON이 **압축 없이** 온다.
   ```
   index.js      받은 81KB / 푼 250KB   ← 압축됨
   /api/stocks   받은 45KB / 푼  45KB   ← 압축 안 됨
   ```
   숫자 표라 gzip을 켜면 6~8KB로 준다. 느린 회선에서 200ms 넘게 빠지는 자리이고
   **프론트에서 할 수 있는 게 없다.** 지금 남은 지렛대 중 제일 크다.

또 하나, `CLAUDE.md`에 적힌 것 중 **틀린 문장이 하나 있다.** 개발 프록시가 허용 목록에
없는 경로를 막을 때 "404가 된다"고 적혀 있는데, 실제로는 **200에 index.html**이 온다
(vite의 SPA 폴백). 중요한 부분은 사실이다 — 요청이 백엔드까지 **안 간다**(로그의
`[차단]`으로 확인). 응답 모양만 다르고, JSON 대신 HTML이 오니 `client.ts`가 실패로
처리하는 결과도 같다. **사용자에게 알렸고 고치지 않기로 두었다.**

## 7. 이어받는 사람에게

**이 문서에서 §3(재는 방법)이 제일 값어치가 크다.** 나머지는 코드와 커밋 메시지를
읽으면 다시 알 수 있지만, 그 함정들은 같은 도구를 쓰면 또 밟는다. 그리고 전부
**결과가 좋아 보이는 쪽으로** 틀렸기 때문에, 의심하지 않으면 그대로 보고하게 된다.

숫자를 하나 보고하기 전에 두 가지를 묻는다.

1. **내 도구가 만든 시간이 섞여 있지 않은가** (스크린샷·대기·route 가로채기)
2. **양쪽을 같은 조건에서 쟀는가** (한쪽만 캐시가 데워져 있지 않은가)
