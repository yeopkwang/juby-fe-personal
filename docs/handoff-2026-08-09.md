## JUBY-BE에서 확인한 사실 (다시 안 파도 되게 적어 둠)

`~/juby-be`를 `git fetch`해서 `dev == origin/dev`임을 확인하고 읽었다.
원격 브랜치 20개 중 백테스트를 건드린 다른 브랜치는 없다.

### 백테스트는 증권사(KIS) API를 거치지 않는다

`/api/backtest/preset`은 **DB만 읽는다.** 새벽 4시 배치가 미리 계산해 둔 값을 꺼내 줄 뿐이다.
지금 우리를 묶어 놓은 계정 정지 위험이 **이 API에는 없다.**

인증도 필요 없다(컨트롤러에 `@AuthenticationPrincipal`이 없다).

### 성향과 전략은 1:1이다

`BacktestService`의 `switch(investType)`가 전략을 결정한다. 요청 DTO에 **전략 필드가 존재한
적이 없다**(2026-06-25 최초 커밋부터 지금까지). 전략 클래스의 `@Order(1~5)`가 성향 번호와
똑같이 매겨져 있고 `EmaStrategy`에만 `@Order`가 없다 — 작성자가 일부러 맞춰 둔 표식이다.

| 성향 | 전략 | 최소 기간 |
| --- | --- | --- |
| 1 안정형 | RSI 역추세 | 1개월 |
| 2 안정추구형 | 볼린저 밴드 돌파 | 3개월 |
| 3 위험중립형 | 이동평균 교차(SMA) | **6개월** |
| 4 적극투자형 | MACD 추세추종 | 3개월 |
| 5 공격투자형 | 돌파 | 3개월 |

### 백엔드 코드에서 발견한 문제

1. 🔴 **거래가 0건이면 안정성이 100점이 된다.** 매매 신호가 안 걸리면 손익 곡선이 평평해
   MDD·변동성이 0이 되고, 안정형은 안정성 비중이 40%라 아무 일도 없이 40점을 먹는다.
   → 화면에서 `거래횟수 0회` 경고를 먼저 띄우게 해 뒀다.
2. 🔴 **고를 수 있다고 해놓고 404가 날 수 있다.** `/preset/options`가 종목과 무관하게
   목록을 만드는데, 배치는 데이터가 모자란 종목을 건너뛴다.
3. 🟡 **짧은 기간일수록 수익률이 뻥튀기된다.** 연환산이 `(1+수익률)^(252/봉수)`라 1개월이면
   12.6제곱이다. 5% 벌면 연 85%로 찍힌다. 하필 1개월은 **안정형만** 쓸 수 있다.
4. 🟡 **돌파 전략의 매도 조건이 `.and()`다.** 돌파선 이탈 **그리고** 손절가 도달을 둘 다
   만족해야 판다. 보통 손절은 `or`다.
5. 🟢 `BACKTEST_FORBIDDEN`(403) 에러코드가 정의만 되고 쓰이지 않는다.
6. 🟢 볼린저 전략의 주석과 코드가 다르다(주석은 중심선, 코드는 하단밴드).

## 앞으로 할 일

### 1순위 — 프리셋이 DB에 실제로 있는지 확인

배치가 한 번도 안 돌았으면 뭘 물어도 404다. **안전하게 확인할 수 있다.**

```
GET /api/backtest/preset/options
```

인증 없음, KIS 안 거침, DB 쿼리 5번. 성향별로 빈 배열이 오면 배치가 안 돈 것이다.
증권사 계정과 무관한 호출이라 이것만 열어보는 건 위험하지 않다.

### 2순위 — API 연결

`src/api/backtest.ts`를 만들어 30줄이면 된다. `getRaw`가 아니라 **`get`**을 쓴다
(`ApiResponse` 래퍼를 쓰는 계열이다).

```ts
export function getPreset(stockCode: string, investType: number, period: BacktestPeriod) {
  return get<BacktestPreset>(
    `/api/backtest/preset?stockCode=${stockCode}&investType=${investType}&period=${period}`,
  )
}
```

붙일 때 함께 할 일:

- `src/utils/backtestSample.ts` 삭제
- `BacktestPage.tsx`의 `SAVED_PERSONALITY` 상수를 `GET /api/members/me/personality`로 교체
  - **로그인이 필요하고, 토큰 없이 부르면 401이 아니라 500이 난다**
  - 로그인해도 성향테스트를 안 했으면 비어 있다 (`personality` 테이블도 비어 있음)
  - 셋 다 "성향 없음"으로 뭉뚱그려 `null` 처리하면 화면은 이미 대응되어 있다
- 종목 성향 판정은 `investType`만 바꿔 5번 호출

### 백엔드에 요청할 것 (우선순위)

1. `/preset/options`에 `stockCode`를 받아 **종목별로** 응답 — 없으면 화면이 404를 띄운다
2. 거래 0건일 때 처리 방침 — 안정성 100점이 의도인지
3. 응답 DTO에 **축별 점수 4개 추가** — 이미 계산해서 로그로만 찍고 버린다
   (지금은 `src/utils/backtest.ts`의 `calculateAxisScores`가 되계산한다. **서버가 주면 삭제**)
4. `InvestPersonality` enum에 `investType` 숫자 추가 — 지금은 프론트가 순서를 가정한다
5. 한 번에 5성향을 주는 엔드포인트 (없어도 5번 부르면 된다)
