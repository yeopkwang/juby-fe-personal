## 0. 시작하는 법

```bash
git clone https://github.com/yeopkwang/juby-fe-personal.git
cd juby-fe-personal
git switch feat/backtest-strategy-cards   # 작업 중인 브랜치. main 아님
```

`.env`는 커밋되어 있지 않다(`.env.example`만 있다). 없어도 화면은 뜬다 —
개발 서버가 `vite.config.ts`의 프록시로 백엔드(`http://3.35.191.42:8080`)에 붙는다.

셋 다 "문법과 타입이 맞다"는 뜻이지 **"화면이 제대로 그려진다"는 뜻이 아니다.**

## 1. ⚠️ 사용자가 정한 규칙 (이걸 모르고 손대면 안 된다)

지난 보름 동안 사용자가 직접 정한 것들이다. **코드만 봐서는 안 보이고, 어긴 적이 있어서
생긴 규칙들이다.** 제안하기 전에 여기부터 본다.

### 절대 하지 않는 것

| 규칙 | 왜 |
| --- | --- |
| **증권사(KIS) API를 브라우저가 직접 부르지 않는다** | app key/secret이 노출된다. 기능명세서 FUNC-002-02가 브라우저 저장을 금지한다. "프론트가 직접 부르면 빠르다"는 제안 자체를 하지 않는다 |
| **스웨거를 보고 API를 붙이지 않는다. 팀 노션에 '완료'로 찍힌 것만** | 스웨거에는 개발 중인 것과 테스트용이 섞여 있다. 그걸 보고 붙였다가 백엔드가 만들지도 않은 API를 부른 적이 있다 |
| **노션은 비공개라 Claude가 못 읽는다** | 새 API를 붙이기 전에 **반드시 사용자에게 노션 표를 받아 대조한다.** 추측으로 붙이지 않는다 |
| **소셜 로그인 버튼에 `fetch`/`axios`를 쓰지 않는다** | OAuth2 리다이렉트라 `window.location.href`로 주소창을 통째로 옮겨야 한다 |
| **화면 컴포넌트에서 직접 `fetch`하지 않는다** | 반드시 `src/api/`를 거친다. `client.ts`가 앱 전체의 유일한 통신 창구다 |
| **토큰을 `src/utils/auth.ts` 밖에서 만지지 않는다** | 나중에 HttpOnly 쿠키로 옮길 때 그 파일만 고치면 되게 하려는 의도. 캐시용 localStorage는 `utils/cache.ts` |
| **`.env`를 커밋하지 않는다** | `.env.example`만 올린다 |
| **뉴스 관련도 정렬을 프론트에서 흉내 내지 않는다** | 사용자: "ㄴㄴ 백엔드에게 명령할거야. 넌 고치지마." 지금은 서버 `sort=RELEVANCE`로 해결됐다 |
| **커밋은 시켰을 때만 한다. push도 마찬가지** | |
| **남의 저장소(`JUBYInvest/JUBY-BE`)를 고치지 않는다** | 백엔드 버그는 사용자가 담당자에게 전달한다. Claude는 읽기만 한다 |

### 손대지 말라고 못 박은 것

## 4. 다음에 할 일

> ✅ **1·2순위와 `SAVED_PERSONALITY`는 2026-08-25에 끝냈다.** 아래 기록은 그때 무엇을

### ~~1순위~~ 끝났다 — 홈이 "실패가 확정된 요청"에 시간을 쓰던 것

`/api/market/**`은 허용 목록에 없어서 `client.ts`가 **fetch에 닿기 전에**
`BlockedPathError`를 던진다. 0초에 결판난 실패다. 그런데 그 위 두 겹이 그걸 모른다.

- `src/api/candles.ts` — `loadRecentCandles`가 `withRetry(…, 2, 400)`.
  400ms 쉬고 또 400ms 쉬고 다시 부른다. **호출 한 건이 0초가 아니라 800ms**가 된다.
- `src/api/home.ts` — `getQuotesFromDaily`가 `settleInChunks(102, 5, …, 120)`.
  5개씩 21덩어리를 사이사이 120ms 쉬며 **끝까지 다 돈다.**

산수로는 `21 × 800ms + 20 × 120ms ≈ 19초`. 앞서 도는 20종목 몫까지 더하면 20초를 넘는다.
**⚠️ 이건 코드를 따라간 계산이고 브라우저로 시계를 재본 값이 아니다. 손대기 전에 먼저 잰다.**

지금 특히 고약한 이유는 `6a07510`에서 **스켈레톤을 넣었기 때문**이다. 예전엔 표가 처음부터
`-`라 "안 되는구나" 하고 넘어갔는데, 지금은 60칸이 20초 동안 반짝이며 "곧 값이 옵니다"라고
말한 뒤 전부 `-`가 된다. 좋은 의도로 넣은 것이 거짓말을 더 길게 하고 있다.

**먼저 재기로 한 약속대로 재고 고쳤다.** 브라우저로 재보니 홈은 첫 화면까지
**5,468ms**를 쓰고 있었다(19~20초는 102종목을 끝까지 내렸을 때 기준의 산수였다).
고친 뒤는 **309ms**다. 실패 경고가 흩어져 찍히던 폭도 4,354ms에서 31ms로 줄었다.

1. `withRetry`가 `isRetryable(error)`이 거짓이면 쉬지 않고 곧바로 던진다.
2. `settleInChunks`가 한 묶음이 통째로 막힌 경로로 떨어지면 남은 묶음을 접는다.
3. `home.ts`의 카드 3장 루프도 같은 이유로 중간에 끊는다(거긴 settleInChunks가 아니다).

⚠️ **2번에는 일부러 `isRetryable`을 쓰지 않았다.** 그걸 쓰면 404까지 '다음 것도
소용없다'로 읽히는데, 404는 **종목 하나가** 없다는 뜻이지 다음 종목도 없다는 뜻이
아니다. 경로가 막힌 것만 종목과 무관하게 전부에 해당한다. 같아 보이지만 다른 질문이다.

### ~~2순위~~ 끝났다 — `client.ts`의 타임아웃

`get<T>()`만 `RequestOptions`를 못 받던 것을 고쳤다(나머지 네 동사는 원래 받고 있었다).

그리고 허용 경로를 실측했다 (2026-08-25, 개발 프록시 경유):

| 창구 | 시간 | 응답 크기 |
| --- | --- | --- |
| 백테스트 프리셋 | 16~38ms | 630B |
| 프리셋 옵션 | 34ms | — |
| 종목 상세 | 38~86ms | 28~45KB |
| 성향 문항 | 51ms | 6KB |

회원 API는 로그인이 막혀 있어 재볼 수가 없다. 그것들을 재고 나면 이 값도 내릴 수 있다.

**뉴스에는 붙이지 않았다.** 지금 502라 정상일 때가 몇 ms인지 모르고, Pinecone이라

## 5. 백엔드에 물어봐야 진도가 나가는 것

**Claude가 백엔드를 고치지 않는다. 사용자가 담당자에게 전달한다.**

### ① 성향 번호표

```sql
SELECT id, invest_personality FROM personality;
```

지금 `utils/personality.ts`의 `PERSONALITY_IDS`가 1~5로 **추정**해 두고, 바꾼 뒤 다시
조회해서 어긋나면 경고를 띄우는 식으로 버티고 있다. 답을 받으면 그 상수만 고치면 된다.

### ② 종목 상세 실시간 — `StockDetailRes`에 `DailyPrices today`

사용자가 상세를 실시간(현재가 + 진행 중인 봉)으로 만들고 싶어 하는데,
**"백엔드 기다렸다 한 번에"** 붙이기로 결정했다. 현재가만 먼저 폴링하는 안은 **거절됐다.**
그때까지 프론트는 손대지 않는다.

막고 있는 것 둘 (조사 끝났으니 다시 파지 말 것):

1. `DailyPriceScheduler`가 `cron = "0 10 22 * * MON-FRI"` — **평일 밤 22:10**에만 채운다.
   장중에는 오늘 봉이 DB에 아예 없다.
2. `StockDetailRes`에 오늘 시·고·저·거래량이 없다. 현재가 하나로는 봉을 못 그린다.
   **백엔드는 이미 갖고 있다** — `CurrentPriceRes.Info`에 다 오는데
   `StockService.getStockDetails()`가 버린다.

붙일 때 정해 둔 값: 폴링 **10초**, **장중에만**, 탭이 백그라운드면 중단(`visibilityState`),
화면 떠나면 중단(이 코드베이스의 `shouldStop` 패턴).
**웹소켓·SSE는 백엔드에 없다**(`build.gradle` 확인). 폴링뿐이다.

### ③ 로그인 — 돌아오는 길이 없다

**프론트는 다 되어 있다.** 나가는 길(`/oauth2/authorization/{naver,kakao,google}`)은
셋 다 302로 제대로 넘긴다. 문제는 백엔드 `OAuth2SuccessHandler`가 주소를 옮기지 않고
`objectMapper.writeValue(...)`로 **JSON을 그려 버리는 것**이다. 사용자는 앱으로 못 돌아오고
백엔드 주소에서 토큰이 적힌 JSON 화면을 본다.

`sendRedirect`로 `/oauth/callback?accessToken=..&refreshToken=..`에 되돌려보내 주면
그때부터 저절로 이어진다. 가짜 토큰으로 전 구간(저장·헤더 갱신·마이페이지·로그아웃) 확인했다.

> 백엔드 담당은 "url로 갈 거야"라고 알고 있는데 코드는 그렇지 않다.
> 이 차이를 모르면 프론트에서 원인을 찾느라 시간을 버린다.

함께 있는 두 번째 버그: **신규 가입이 구글·카카오에서 500.**
`GoogleResponse`/`KakaoResponse`의 `getBirthyear()`·`getBirthday()`가 진짜 `null`이 아니라
**문자열 `"null"`**을 돌려주는데 `parseBirth()`는 진짜 `null`만 걸러내서
`LocalDate.parse("null-null")`까지 가서 터진다. 기존 회원은 무사하다.

손으로 확인하려면 JSON에서 토큰을 복사해
`/oauth/callback?accessToken=붙여넣기&refreshToken=붙여넣기`로 직접 들어간다.

### ④ 홈 시세 — `GET /v1/home`

홈이 `/api/market/**`에 매여 있는 한 시세는 계속 `-`다. 백엔드가 시세까지 담은 창구를
만들어 주면 `home.ts`의 `getHomeStocks()`가 그걸 반환하도록 바꾸면 된다.
**프론트가 KIS를 직접 부르는 우회는 없다**(1절 참고).
